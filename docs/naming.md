# 命名决策记录

## 定名

**`dsh-mixer`（调音台 / Mixer）**

| 项 | 值 |
| --- | --- |
| 插件包名 | `dsh-mixer` |
| Cordis 行 id | `dsh-mixer` |
| 切换指令 | `/mixer` |
| 视图切换按钮 | 「调音台 ⇄ 常规」 |
| i18n 前缀 | `mixer.*` |
| 中文名 / 英文名 | 调音台 / Mixer |

## 为什么是调音台

调音台的物理形态与这个需求几乎一一对应：

- **多通道并排，每路独立** —— 对应"多个会话横向并列，各自有独立输入框"。每一路通道条有自己的推子和输入源。
- **状态一眼可见** —— 调音台上哪一路有信号、哪一路被静音、哪一路推子拉满，全是灯和电平表，不用逐个点开。对应"谁卡在决策/权限申请"。
- **后续交互不用重新编故事** —— `solo`（只听这一路）对应"聚焦某个会话"，`mute`（静音这一路）对应"暂时收起某格"。术语已经在那里了。

## 术语表

| 术语 | key 空间 | 含义 |
| --- | --- | --- |
| channel | `mixer.channel.*` | 每一格会话面板 |
| waiting | `mixer.waiting.*` | 该通道在等你决策 / 授权 |
| solo | `mixer.solo.*` | 只聚焦一个通道 |
| 移出 / put away | 二期接 locale 时再定 key 空间（原拟 `mixer.mute.*`） | 暂时从调音台收起一个通道；会话本身不受影响，可放回 |

> ⚠️ 2026-10-15 定名：`×` 的那个行为叫**移出（put away）**，**不叫 `mute`**；`mute` 一词保留给将来"通道还在、只是不打扰"的能力，与 `solo` 同族。见 `CONTEXT.md` 与 `docs/spec.md` §9.1。

## 落选方案

第一批（布局隐喻）：

| 名字 | 落选原因 |
| --- | --- |
| `dsh-mosaic` | 语义够贴，但只讲"拼在一起"，不讲"谁在等你" |
| `dsh-cockpit` | 告警语义强，但"横向并排对话"的画面感弱 |
| `dsh-tiles` / `dsh-grid` | 太通用，像纯布局库，且 grid 重名风险高 |
| `dsh-panorama` | 好听但读长，缩写 `pano` 不顺口 |
| `dsh-desk` | 太泛，说不清是干什么的 |

第二批：

| 名字 | 落选原因 |
| --- | --- |
| `dsh-tower`（塔台） | 双关好（clearance = 权限许可），但整体偏"调度"味，与"每格独立对话"稍远 |
| `dsh-lanes` / `dsh-swimlane`（泳道） | 语义准，但"泳道"是流程图术语，且告警感弱 |
| `dsh-bento`（格子） | 中文"便当"怪，偏静态排版，不表达独立输入 |
| `dsh-conductor`（指挥台） | 气质好，但名字偏长，缩写 `cond` 不好听 |
| `dsh-radar`（雷达） | 只讲"看"，不讲"每格能独立对话" |
| `dsh-deck`（牌组） | 歧义多（甲板 / 牌组 / 演示文稿） |
| `dsh-fleet` / `dsh-docks` / `dsh-bays` | 偏"集群/停靠"味，与并行推进的语义有偏差 |

结论：`dsh-mixer` 是唯一让「独立输入」和「谁在等你」共用一个隐喻、且后续交互（solo / 移出（put away） / 状态灯）能自然生长的名字。
